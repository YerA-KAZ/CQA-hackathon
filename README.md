# CQA Freedom Broker
TEAM : Новое название

Прототип контроля качества чатов и звонков. FastAPI загружает диалоги и отдаёт интерфейс, Ollama локально оценивает каждый критерий, SQLite хранит оценки, апелляции и версии чек-листа.

## Запуск на Windows

Понадобятся Git, Python 3.11+ и запущенная Ollama. Команды выполняются в PowerShell, в том числе во встроенном терминале VS Code.

```powershell
git clone https://github.com/YerA-KAZ/CQA-hackathon.git
Set-Location CQA-hackathon
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Укажите в `.env` полный подписанный URL в `CQA_API_URL`, включая параметры подписи, который вы получили от организаторов, и точное имя локально установленной модели в `OLLAMA_MODEL`. Команда `ollama list` показывает установленные модели. Если список пуст, скачайте модель из примера командой `ollama pull qwen3.5:4b`. При смене модели обновите `OLLAMA_MODEL` и перезапустите приложение. Адрес Ollama по умолчанию — `http://127.0.0.1:11434`.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.api:app --env-file .env
```

Откройте [интерфейс CQA](http://127.0.0.1:8000) или [документацию API](http://127.0.0.1:8000/docs). У приложения нет авторизации, поэтому для локального запуска оставьте адрес привязки по умолчанию.

1. Загрузите группу DEV и выберите диалог.
2. Нажмите «Оценить». Оценка идёт в запросе последовательно по критериям. Дождитесь результата.
3. Откройте реплику-доказательство. Для звонка можно перейти к этому моменту записи.
4. Подайте апелляцию на критерий и сохраните решение с причиной. Исходный вердикт останется в карточке.
5. Измените критерий через поля редактора или в режиме JSON и примените чек-лист. Таблица покажет изменившиеся итоги. Применение пересчитывает все загруженные диалоги и использует кэш неизменённых критериев.

Без URL организаторов интерфейс и документация API откроются, но кнопка импорта не загрузит DEV.

Для контрольной выборки введите выданный организаторами `group_id`. Для чистого прогона можно задать отдельный `CQA_DB_PATH` в `.env` и перезапустить сервер. Данные и база по умолчанию находятся в игнорируемой папке `data/`. Подписанные ссылки и ручную разметку храните там или в другой папке вне Git.

## Метрики на ручной разметке

Сохраните независимую разметку в `data/reference.json`. Пример с вымышленным ID и несколькими критериями.

```json
[
  {
    "conversation_id": "fixture-1",
    "language": "KZ",
    "answers": {"01": "yes", "02": "n/a", "04": 15, "08": "no"}
  }
]
```

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_metrics.py --reference data/reference.json
```

По умолчанию скрипт сравнивает исходные ответы модели. Флаг `--final` учитывает решения по апелляциям. Отчёт содержит разбивку по языкам и критериям, точное совпадение, среднее абсолютное отклонение по шкале и TP/FP/FN для N/A и флага 08. Пропущенные ответы снижают долю точных совпадений и отдельно учитываются в `missing`. Они исключены из отклонения по шкале и подсчёта TP/FP/FN.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют синтетические диалоги, ответы модели и API. Спорные правила описаны в `app/config/assumptions.json`. Шаблоны событий предварительные. Для модели ещё нужно измерить качество на RU, KZ и EN и время прогона десяти диалогов.
